# SOP: Client Onboarding

## Singhaya Online

**Digital Ecosystem for Wellness Brands**

This SOP explains the standard process for receiving, evaluating, onboarding, and managing new clients for Singhaya Online.

---

## 1. Client Inquiry

When a new client contacts Singhaya Online, collect the basic information first.

### Basic Information

- Business Name:
- Contact Person:
- Phone / Line / WhatsApp:
- Email:
- Website / Facebook / Instagram:
- Business Type:
- Location:
- Main Problem:
- Service Needed:
- Budget Range:
- Expected Start Date:

## 4. Initial Assessment

Before offering a price, check:

- Does the client already have a website?
- Does the client have logo / brand assets?
- Does the client have social media channels?
- Does the client have admin access?
- Does the client have product or service details ready?
- Does the client need urgent work?
- Does the client understand monthly service terms?
- Is this a good-fit client for Singhaya Online?

---

## 5. Proposal Preparation

Prepare a simple proposal with:

- Client problem
- Recommended solution
- Scope of work
- Timeline
- Monthly fee or project fee
- Payment terms
- What is included

## 8. Client Folder Structure

Each client should have a folder under:

```text
clients/client-name/
├── brief.md
├── proposal.md
├── content-plan.md
├── access-note.md
├── change-log.md
└── monthly-report.md
```
---
### File Purpose

- `brief.md` = Client information, business background, problems, goals, and requirements
- `proposal.md` = Scope of work, pricing, timeline, payment terms, and next steps
- `content-plan.md` = Monthly content plan, campaign ideas, posting schedule, and marketing direction
- `access-note.md` = Notes about access channels only, such as website, Facebook Page, Line OA, hosting provider, or email provider. Do not store passwords here.
- `change-log.md` = Record of website, content, design, SEO, CRM, or system updates for this client
- `monthly-report.md` = Monthly work summary, completed tasks, pending tasks, client feedback, and next month plan

Do not store passwords directly in GitHub.

## 9. Monthly Workflow

Every month, update and review the following:

- Work completed
- Pending tasks
- Content published
- Website updates
- SEO updates
- Social media updates
- CRM or booking system updates
- Client feedback
- Problems found
- Recommended next steps
- Next month plan
- Payment status

The monthly workflow helps Singhaya Online manage clients professionally, reduce confusion, and prepare for team expansion in the future.

---

## 10. Security Rule

Do not store the following information in GitHub:

- Passwords
- API keys
- Bank information
- Customer private data
- Database backups
- Confidential contracts
- Certificate records
- Personal health information
- Login credentials
- Payment details

If access information is needed, record only the platform name, ownership status, and responsible person. Do not record the actual password or secret key.

---

### Access Note Example

```text
Website access: Held by client
Facebook Page access: Admin invited
Hosting access: To be confirmed
Line OA access: Client owns account
Google Drive access: Shared with Singhaya Online
CRM access: Admin account to be created
```

## 11. Internal Rule

Every important update must be recorded in:

```text
docs/change-log.md
```

Use the change log whenever there is an update related to:

- Website
- Branding
- Content
- SEO
- CRM
- Booking system
- Client documents
- Monthly service
- Proposal
- System setup
- Access structure
- Digital workflow
- Client communication
- Website maintenance

### Update Format

When recording an update, include:

- Date
- Area
- Change
- Person
- Status
- Notes

### Example

```text
19 June 2026 | SOP | Added client onboarding SOP | Kete Singh | Done | SOP stored in docs/sop-client-onboarding.md
```
